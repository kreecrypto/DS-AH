# Form

## Rules
Group fields by user task, not database schema. Use persistent labels. Mark requirements clearly. Choose controls that match input semantics. Validate at a useful moment. Preserve entered data after recoverable errors.

## Errors
Identify the field/problem, explain correction, and provide summary/focus strategy for long forms where appropriate.

## States
Empty, partially complete, valid, invalid, submitting, submission error, success, read-only, disabled.

## Accessibility
Programmatic labels, instructions, required state, error association, keyboard order and appropriate autocomplete/input semantics in implementation.

## Validation
Completion, abandonment, correction loops, error frequency and time on task.
