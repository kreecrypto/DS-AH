# Information Architecture Skill

## Purpose
Ensure information is grouped, ordered, labeled and exposed according to user tasks and approved product structure.

## Trigger
Mandatory for CREATE/MODIFY/REVIEW when information hierarchy, grouping, navigation, filtering, forms, tables, dashboards, detail pages, or content organization is involved.

## Required inputs
- user goal/task
- approved reference or explicit EXPLORE brief
- current content/data fields
- product/domain patterns

## Procedure
1. Identify the primary user task and decision.
2. Inventory visible information/actions.
3. Separate primary, secondary and supporting information.
4. Group items by user mental model and task sequence.
5. Verify section order and progressive disclosure.
6. Check navigation/findability and return paths.
7. Check taxonomy, naming consistency and duplicate concepts.
8. Check filters/search/sort placement against task frequency.
9. Check whether hidden/collapsed content preserves discoverability.
10. For ADAPT, compare the proposed change against the existing IA and limit changes to the requested scope.

## IA Gate
PASS only when:
- primary task is obvious
- group boundaries are coherent
- ordering supports task sequence
- labels map to the same concepts consistently
- no required information is stranded or duplicated
- navigation/return path is clear where relevant

## Review findings
Record:
- observation
- user impact
- affected group/navigation
- proposed bounded change
- acceptance criteria

## Hard rules
- Do not reorganize approved IA for visual preference alone.
- Do not create new navigation levels unless task/content evidence requires them.
- Do not solve density only by hiding important content.
- In REPRODUCE, preserve approved IA unless the user explicitly requests change.

## Evidence
- task hierarchy
- content grouping
- section order
- navigation/findability result
- taxonomy/label result
- IA gate result
